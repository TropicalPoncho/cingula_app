<objective>
INFRA-01 + INFRA-02 contra un deploy REAL: cambiar la Root Directory del proyecto Vercel único,
crear un Preview de `ws/web` y probarlo con los scripts de Wave 0, antes de cualquier merge a `main`.

**Riesgo de la ventana (va primero, per CLAUDE.md regla de oro):** la Root Directory es un setting
global del proyecto, no por rama. Cambiarla NO afecta al deploy de producción que ya está vivo
(los settings aplican solo a builds nuevos), pero desde ese momento cualquier build NUEVO de
producción desde `main` (que todavía no tiene `web/api/`) saldría sin funciones -> `/sync/*` caído
para el celular. El outbox del celular reintenta (RNF-03), así que no hay pérdida de datos, pero
hay que evitarlo:
- Solo aplica si el proyecto está conectado a Git (respuesta 1.c del 11-02). Si los deploys de
  producción son manuales (`vercel --prod`), la ventana no existe mientras nadie corra ese comando.
- Mitigación: no pushear a `main` (ningún workstream, incluido `app`) entre este plan y el merge
  del plan 05; mantener la ventana en minutos/horas, no días.
- Rollback inmediato si algo sale mal: Settings -> Root Directory de vuelta a `backend` (lo que
  había) y, si ya se construyó un prod roto, Deployments -> último deploy de producción sano ->
  "Instant Rollback". `backend/vercel.json` sigue en `main`, así que volver a `backend` funciona.

Output: Preview verificado (ruteo + base dev), producción en vivo verificada sin cambios.
</objective>

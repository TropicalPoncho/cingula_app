<objective>
Primer plan de la Fase 12: dejar la SPA (Vite + React 19, JS sin TypeScript, router propio — D-01,
D-19) servida desde el MISMO proyecto Vercel que `web/api/`, con la pantalla de Acceso real (AUTH-02)
validando la clave contra el backend, y la entrega verificada en un Preview real antes de que nada
llegue a `main`.

Purpose: es la pieza de mayor riesgo de la fase. Un `vercel.json` con el fallback de SPA mal
ordenado puede tragarse `/sync/push` del celular en producción (research H1, Pitfall 1) y `vercel dev`
no sirve para probarlo en este equipo. El tracer prueba la arquitectura de punta a punta (navegador
-> router -> sesión -> función real -> Neon) antes de construir el resto.
Output: andamiaje Vite + DS + infraestructura de tests (Vitest + Playwright), Acceso + shell
autenticado, `vercel.json` final, smoke extendido y un Preview con `SMOKE OK`.

## Decisión de arquitectura registrada (va a Notion como ADR al cerrar la fase)

| Qué se decidió | Por qué | Alternativas descartadas | Riesgo mientras no se valide |
|----------------|---------|--------------------------|------------------------------|
| La SPA es un proyecto Vite dentro de `web/`, junto a `web/api/`, en el mismo proyecto Vercel (Root Directory `web`, 11-04). `web/vercel.json` declara `framework: "vite"`, `buildCommand: "npm run build"`, `outputDirectory: "dist"`, el rewrite `/sync/:path*` -> `/api/sync/:path*` PRIMERO (hoy es la única regla: `web/vercel.json:1-5`) y después un fallback SPA con exclusiones `(?!api/|sync/|assets/)` y sin punto; más headers de seguridad. | Vercel da precedencia al filesystem (estáticos de `dist/` y funciones de `api/`) antes de los rewrites, y procesa los rewrites en orden (research Pattern 1, docs citadas). Un solo proyecto = mismo origen: CSP `connect-src 'self'`, sin CORS. | Proyecto Vercel separado para la SPA (dos deploys, CORS, otra variable de entorno); Next.js (D-01); fallback `/(.*)` sin exclusiones (queda como respaldo documentado si el Preview rechaza la regex, A1). | Las asunciones A1 (regex aceptada) y A2 (el preset `vite` no altera el descubrimiento de `api/`) sólo se validan en un Preview real (H1). Mergear a `main` sin ese smoke cambia el ruteo del push del celular en producción. Mitigado: gate de Preview en este plan + compuerta humana con el celular en 12-10. Si igual se colara HTML en `/sync/push`, el celular no pierde datos: `jsonDecode` lanza ante HTML (`lib/data/sync/sync_api_http.dart:41`) y el outbox reintenta. |

Hallazgo nuevo (no estaba en el research): Production NO tiene `WEB_API_KEY` (`npx vercel@latest env ls
production` 2026-10-06 lista sólo `SYNC_API_KEY`). No bloquea este plan (el Preview sí la tiene,
11-04); el plan 12-03 la crea en Production antes de la medición y del login real en producción.

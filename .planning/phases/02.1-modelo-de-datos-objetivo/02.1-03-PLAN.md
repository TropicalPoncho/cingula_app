2. **paths + obras de route**: `SELECT * FROM geo_paths`. Por cada fila: uuid del path = el existente o v4 nuevo; `obra_uuid = obraUuidForPath(pathUuid)`; crear la obra con `name` = el nombre del path, `visibility='draft'`, `owner_id` NULL, `share_token` NULL, `updated_at`/`logical_version` tomados del path (`?? nowSec` / `?? 1`) — que la obra herede los metadatos del path es lo que hace que el celular y el script de Neon generen filas idénticas. Guardar `pathUuidById`. Insertar `path_progress` con `saved_offset_ms` de la fila (incluso si es 0) y `updated_at = nowSec`.

3. **triggers + portales**: `SELECT * FROM geo_triggers ORDER BY geo_path_id, offset_ms, id`. Por cada fila: uuid del trigger = el existente o v4 nuevo.
   - Si `geo_path_id` no es NULL y existe en `pathUuidById` → `path_uuid = pathUuidById[geo_path_id]`.
   - Si `geo_path_id` es NULL, **o apunta a un path inexistente** (referencia colgante — NUNCA descartar la fila): crear un path portal: `pathUuid = portalUuidForTrigger(triggerUuid)`, `kind='portal'`, `name` = el nombre del trigger, `audio_uuid = audioUuidById[audio_asset_id]`, `tolerance_meters = 10.0`, y su obra `obraUuidForPath(pathUuid)` con el nombre del trigger y `visibility='draft'`. Es seguro porque el monitor de hoy, cuando el trigger tiene `geo_path_id`, reproduce SIEMPRE el audio del path e ignora el del trigger (`monitor_user_location_usecase.dart` líneas 253-275); y los sueltos se llevan su audio al portal.

4. **cobertura de cada obra**: agrupar los triggers ya migrados por `path_uuid → obra_uuid`, llamar a `computeCover` con sus lat/lon y escribir `cover_lat/cover_lon/cover_min_lat/cover_max_lat/cover_min_lon/cover_max_lon` en la obra. Obra sin triggers → las seis columnas en NULL (D-29).

5. **verificación** (`Future<void> _verify(DatabaseExecutor db, Map<String,Object?> before, int nowSec)`, lanza `MigrationException(mensaje, report: {...before, ...conteosDespués})` al primer fallo):

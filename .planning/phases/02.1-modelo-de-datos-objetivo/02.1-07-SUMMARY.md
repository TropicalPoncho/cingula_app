- `--apply` (x2) and post-migration `npm test`: still not run — blocked by the new validation abort, which happens before any write.

## Deviations from Plan

**1. [Rule 4 - architectural, resolved by user] Ambiguous (table,id)->uuid map.** The user inspected the read-only phone DB copy and identified the live uuid for each of the 4 ambiguous keys. Implemented as an explicit override map (`backend/scripts/id_overrides.json`) consumed by `buildIdMap`/`translate`; keys without an override still abort. Files: `backend/scripts/translate.js`, `backend/scripts/translate.test.js`, `backend/scripts/migrate_v2.mjs`, `backend/scripts/id_overrides.json`.

**2. [Rule 4 - architectural, NOT resolved] Missing title/name on ~117 rows.** Discovered during the re-run, one abort layer past the id-ambiguity fix. Not a bug introduced by this remediation — it is a pre-existing gap in what's stored in `synced_entities` (old v6 client apparently pushed partial, not full-row, payloads for updates; the base fields fell out of history beyond the server's current+1-previous retention). Not auto-fixed: writing a placeholder name/title into the typed tables now would be a real data-integrity risk given 02.1-RESEARCH.md's cutover design (the phone's future full resend is a same-version no-op for untouched entities, so it would NOT self-heal a placeholder). Left for an explicit owner decision before 02.1-12 (see 02.1-NEON-REHEARSAL.md, "Remediation re-run" section, for the options considered).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps |
| sm | 8px | Compact element spacing (e.g. between switch and helper text) |
| md | 16px | Default screen/card padding (already used: `home_page_impl.dart:30` screen padding, `audio_details.dart:11` card padding uses 12px — see exception) |
| lg | 24px | Section breaks in the scroll column (already used: `home_page_impl.dart:40`) |
| xl | 32px | Gap between the status hero and the monitoring control in user mode |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- `AudioDetails` card currently uses 12px internal padding (`audio_details.dart:11`) — pre-existing, out of scope to refactor this phase since the widget itself isn't touched; new user-mode surfaces must use 16px, not 12px.
- 96px bottom scroll padding (`home_page_impl.dart:30`) is FAB clearance, not a spacing token — valid as 12×8, keep as-is.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular (400) | 1.5 |
| Label | 14px | regular (400) | 1.4 |
| Heading | 20px | bold (700) | 1.2 |
| Display | 22px | bold (700) | 1.2 |

Weight choice: 400/700 (not 400/600) because `FontWeight.bold` (=700) is already the emphasis weight used twice in the codebase (`audio_details.dart:16`, `home_page_impl.dart:153`) — reuse it instead of introducing a third weight.

Usage:
- Display (22/700): AppBar title "Cingula" — also the hidden-gesture tap target (D-07).
- Heading (20/700): card/section titles (e.g. `AudioDetails` title).
- Body (16/400): primary status text, monitoring subtitle, DB-recovery banner body.
- Label (14/400): secondary/support text, FAB label, timer digits.

## Color

Project uses Material 3 **seeded dynamic color** (`ColorScheme.fromSeed(seedColor: Colors.teal)`, seed hex `#009688`), not static hex tokens — exact tone hexes are resolved by the Material 3 algorithm at build time. Reference by `ColorScheme` role, not hardcoded hex, so this stays correct if the seed ever changes.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Theme.of(context).colorScheme.surface` | Scaffold background of the user-mode home screen |
| Secondary (30%) | `Theme.of(context).colorScheme.surfaceContainer` | `AppBar` background, `Card` surfaces (`AudioDetails`), the monitoring `SwitchListTile` row |
| Accent (10%) | `Theme.of(context).colorScheme.primary` | Reserved for: the Iniciar/Detener `FloatingActionButton`, the active-monitoring status icon+text, the `SwitchListTile` active track/thumb (Material 3 default binding) |
| Destructive | `Theme.of(context).colorScheme.error` | Reserved for: the DB-recovery problem banner/dialog only (D-02) — this is the only "something went wrong" surface a user can see in this phase |

Accent reserved for: FAB, active-monitoring indicator, active switch state — nothing else (no accent on plain text links, section titles, or static icons).

Note: `_RecordingBanner`'s red mic indicator (`home_page_impl.dart:137-147`) stays hardcoded `Colors.red.*` because it is debug-only and hidden entirely in user mode (D-10) — not part of this color contract.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Iniciar" / "Detener" — existing FAB toggle label, unchanged per D-11 (do not rename) |
| Empty state heading | "Listo para iniciar" — existing `SwitchListTile` subtitle default (`home_page_impl.dart:36`), reuse as-is |
| Empty state body | When monitoring is on and no audio is currently playing, `PlaybackNotifier.statusMessage` fills this slot — use: "Caminando… te avisamos cuando estés cerca de un punto sonoro." |
| Error state | DB-recovery banner (D-01/D-02), non-blocking `MaterialBanner` shown after normal startup completes (never a blocking dialog — app must stay usable mid-recording): Heading "Base de datos restaurada automáticamente" / Body "Detectamos un problema al abrir tus datos. Guardamos una copia en `cingula.db.corrupto-<yyyyMMdd-HHmmss>` y la app sigue funcionando con normalidad." / Action "Entendido" (dismiss) |
| Destructive confirmation | None remain in scope — `recreateForTesting()` and `importDatabase()` UI entry points are deleted outright (D-03/D-04), not gated behind confirmation |

Mode-toggle feedback (interaction note, not a separate screen): the hidden gesture is 5 taps on the AppBar title within 3 seconds (standard "secret menu" convention — no visible chrome, matches D-07's "no ocupa espacio en la UI"). On success, show a 2-second `SnackBar`: "Modo debug activado" / "Modo usuario activado" — this is the only feedback the toggle gets, since the gesture itself must stay undiscoverable.

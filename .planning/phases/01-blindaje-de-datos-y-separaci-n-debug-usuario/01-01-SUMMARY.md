# Phase 01 Plan 01: Blindaje de Base de Datos Summary

**Rename-not-delete recovery for `cingula.db` on open failure, plus removal of every destructive debug action (recreate/import DB) from the UI and `AppDatabase` API.**

## Performance

- **Duration:** ~15 min
- **Completed:** 2026-08-08
- **Tasks:** 2
- **Files modified:** 6 (2 created, 4 modified)

## Accomplishments
- `AppDatabase.init()` no longer calls `deleteDatabase()` on open failure — it renames the existing file (and its `-wal`/`-shm`/`-journal` sidecars) to `cingula.db.corrupto-<yyyyMMdd-HHmmss>` and opens a fresh database, recording the event in `lastRecoveryEvent`.
- `db_recovery.dart` is a pure-Dart module (`dart:io` only) so the rename/timestamp logic is unit-tested against a temp directory, no sqflite/path_provider/device needed.
- `data_browser_page.dart` and `AppDatabase` no longer expose any way to recreate or overwrite the local database — `_recreateDb`/`_importDb`, `recreateForTesting()`, `importDatabase()`, and the `file_picker` dependency are all gone. `exportDatabase()` and `getDatabaseStats()` (non-destructive) are untouched.
